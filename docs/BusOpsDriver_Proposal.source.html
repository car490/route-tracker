1. Executive Summary

This proposal, powered by CoachMate, introduces a modern interior passenger information display system designed specifically for older fleet vehicles such as the Volvo B7RLE. The system uses a controller-driven HDMI display, bypassing legacy DG3/IBIS hardware entirely. This delivers a passenger information experience using UK-sourced components, with minimal electrical integration and full control over the UI.

The solution is:

  • Modern — full graphics, animations, branding
  • Compatible — works with any older bus
  • Maintainable — uses standard, UK-stocked components
  • Cost-effective — avoids EG4/Ethernet retrofits
  • Deterministic — the Bus Controller drives all display logic
  • Regulation-aware — designed against the PSV Accessible Information Regulations 2023 display requirements; see Appendix A for the full compliance mapping

2. System Architecture Overview

High-Level Architecture

24V Bus Supply --> Victron Orion-Tr Isolated 24/12 DC-DC Converter --> Fused 12V
Distribution --> [Bus Controller, Interior Display, Driver PWA charging] --HDMI--> Interior Display

Application Flow

Operations PWA Creates routes, duties, schedules. Sends duty link to driver.

Driver PWA Receives duty link. If none: shows Route Selector. On Start: begins GPS polling and progress tracking. Joins the Bus Controller's local WiFi access point and sends structured progress events to it over that link.

Bus Controller Hosts a local WiFi access point for the Driver PWA to join. Receives progress events. Renders final UI. Outputs HDMI to interior display.

Interior Display Shows the passenger information UI.

3. Driver PWA (Dedicated Chapter)

The heart of the platform's real-time intelligence

The Driver PWA is the operational core of the ecosystem. It is responsible for:

  • Duty retrieval
  • Route selection
  • GPS polling
  • Stop detection
  • Progress tracking
  • Sending structured progress events to the Bus Controller

It runs on a dedicated tablet mounted in the driver's cab.

3.1 Driver PWA Responsibilities

Duty Handling

  • Receives duty link from Operations PWA
  • Displays duty summary
  • If no duty: presents Route Selector
  • Ensures driver starts correct route

GPS Polling

  • Polls GPS at fixed intervals
  • Calculates distance to next stop
  • Determines stop arrival/leave events
  • Detects terminus arrival

Progress Event Generation

Driver PWA sends structured JSON events to the Bus Controller, including:

  • next_stop
  • following_stop
  • distance_to_next
  • eta_next_stop
  • progress_percent
  • stop_requested
  • disruption_message
  • terminus_flag

Connectivity

Corrected: the Bus Controller hosts the local network (a hostapd WiFi access point); the Driver PWA device joins it as a standard, low-privilege WiFi client. The device does not host its own hotspot.
  • Joins the Bus Controller's WiFi access point as a client
  • No pairing step required on the tablet beyond the one-time WiFi join
  • USB tether (optional, bench/diagnostic use only)

6. Installation Plan (Volvo B7RLE)

6.1 Mechanical Installation

  1. Identify roof structure/cross-members above the aisle, just past the entry area.
  2. Install VESA ceiling-drop mount (75×75, rated for the panel's ~10kg) with M8 bolt-through fixings into the roof structure.
  3. Add anti-vibration isolation mounts.
  4. Mount the Interior Display to the ceiling-drop mount.
  5. Install the Bus Controller (Raspberry Pi 5) and power electronics together in a single polycarbonate enclosure, recessed into the same ceiling void. Polycarbonate is specifically required, not metal — a metal enclosure would attenuate the Pi's onboard WiFi (Faraday-cage effect), which the Driver PWA depends on to reach the access point it hosts.
  6. Install the Driver PWA tablet mount in the cab using a RAM Mounts C-size ball-and-socket cradle on a bolted (not suction-cup) base, rated for commercial-vehicle vibration.

6.2 Electrical Installation

  1. Tap into auxiliary 24V circuit, downstream of the vehicle's master isolator switch.
  2. Install input fuse ahead of the Victron Orion-Tr Isolated 24/12 converter, and an output fuse per branch off the 12V distribution block.
  3. Mount the converter and fused distribution block in the enclosure.
  4. Run 12V to the Interior Display (native 12V input).
  5. Run 12V to a USB-C PD module powering the Raspberry Pi 5 (5V/5A over USB-C).
  6. Run 12V to a USB-C PD module for Driver PWA tablet charging at the cab mount.
  7. Install ferrite chokes on power lines.
  8. Run shielded HDMI cable from the Bus Controller to the Interior Display.

6.3 Software Commissioning

  1. Install Raspberry Pi OS, boot from USB3/NVMe SSD (avoids SD-card corruption risk on ungraceful power loss).
  2. Configure hostapd WiFi access point on the Pi (with the WiFi interface marked unmanaged in NetworkManager so it doesn't fight the manually-run hostapd), and configure auto-boot systemd services for both the AP and the kiosk browser.
  3. Pair the Driver PWA tablet to the Pi's access point (one-time WiFi join at commissioning).
  4. Set HDMI output to the panel's native 1920×360 resolution.
  5. Test UI transitions and brightness for daylight visibility through the vehicle glazing.
  6. Perform road test for readability, stability, and AP reconnect behaviour after a power cycle.

Appendix A: PSV Accessible Information Regulations (PSV(AI)R) Compliance

Prepared against two source documents supplied by the operator: the CPT Operator Checklist for Vehicle Compliance (display, audio, and announcement requirements), and the accompanying CPT guidance note on diversions, hail-and-ride, and Annexes A (volume measurement) and B (alerts).

The Interior Display System described in the body of this proposal delivers the visual display rows (Section A1) and receives the disruption/diversion text shown on-screen.
